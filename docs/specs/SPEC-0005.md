# SPEC-0005: Resource Classification, Data Egress & Secrets v1

**Status:** Accepted
**Version:** 1.0
**Date:** 2026-09-04
**Supersedes:** None

## Scope

This specification defines Resource classification levels, data egress authorization, credential brokering, and sentinel-secret conformance testing for Forge VNext.

## Definitions

- **Resource classification**: A sensitivity label applied to a Resource or Artifact.
- **Data egress**: Transfer of data outside the Forge process boundary (to a model provider, external API, public internet, etc.).
- **Destination class**: A category of external destination for egress authorization.
- **Credential broker**: A trusted component that provides credentials to authorized adapters without exposing them to untrusted processes.
- **Sentinel secret**: A test value used to prove that sensitive data does not leak through a given path.
- **Declassification**: The explicit, trusted process of reducing a Resource's classification level.

## Normative requirements

### R1: Classification levels

Forge MUST support at minimum these classification levels:

| Level | Meaning | Examples |
|---|---|---|
| `PUBLIC` | No sensitivity; may be freely disclosed | Public documentation, open-source code |
| `INTERNAL` | Internal operational data; not for public disclosure | Task titles, project names, configuration |
| `CONFIDENTIAL` | Sensitive business or personal data | Customer data, credentials, private repositories |
| `SECRET` | Highly sensitive; strict access control required | Authentication keys, financial records, PII |

### R2: Derived Artifact classification

An Artifact derived from one or more input Resources MUST have a classification at least the maximum of its inputs' classifications.

```
artifact.classification = max(input[0..n].classification)
```

A model summary or generated output does NOT declassify confidential data.

### R3: Declassification

Declassification (reducing classification level) MUST only occur through:

- An explicit trusted transformation with a versioned policy.
- Operator approval.
- An audit record of the declassification decision.

Declassification MUST NOT occur through:

- Model output.
- Package text.
- Feature flags.
- Implicit passage of time.

### R4: Egress authorization order

Egress authorization MUST follow this order:

1. **Classification** of the data to be egressed.
2. **Destination eligibility** check against classification policy.
3. **Grant/egress authorization** — does the Principal have a Grant allowing this egress?
4. **Construct query/prompt** — only after authorization passes.

The following order is FORBIDDEN:

```
construct sensitive prompt → later discover provider/destination disallowed
```

### R5: Destination classes

Forge MUST distinguish at minimum these destination classes:

| Class | Description |
|---|---|
| `local_only` | Must never leave the local process or host |
| `approved_private_service` | Approved private/internal service (e.g., internal API, on-premise model) |
| `approved_cloud_model` | Approved cloud model provider (e.g., specific configured API endpoint) |
| `public_internet` | General public internet destination (web search, public API) |

### R6: Classification-to-destination matrix

Egress MUST be denied unless the combination is explicitly permitted:

| Classification | local_only | approved_private_service | approved_cloud_model | public_internet |
|---|---|---|---|---|
| PUBLIC | MAY | MAY | MAY | MAY (with policy) |
| INTERNAL | MUST | SHOULD | MAY (with policy) | DENY |
| CONFIDENTIAL | MUST | MUST | MAY (with strict policy) | DENY |
| SECRET | MUST | MUST (with audit) | DENY | DENY |

### R7: External Resource contents are untrusted

Contents obtained from external Resources (repository files, web pages, API responses, model output) MUST be treated as untrusted data.

Untrusted data MUST NOT:

- Grant Capabilities.
- Alter policy.
- Widen Resource access.
- Change routing decisions.
- Increase budget.
- Request secrets.
- Disable verification.
- Modify Grants.
- Alter authorization decisions.

### R8: Credential brokering

Credentials SHOULD be brokered through trusted adapters rather than passed to general model processes.

Where possible:

- Credentials MUST be audience/resource scoped (valid only for the intended service).
- Credentials MUST be injected at the adapter layer, not passed through the model context.
- Token passthrough between unrelated services is PROHIBITED.

### R9: Sentinel-secret conformance

Sentinel-secret conformance tests MUST verify that a known secret value placed in the following locations does not leak outside approved boundaries:

- Task titles
- Resource contents
- Environment variables
- Credential fields
- Error messages
- URLs and query parameters
- Log output
- Artifact metadata
- Model context (prompts)
- Adapter responses

## Data/state model

### resource_classification table

```
resource_id: UUID
resource_type: string
classification: enum(PUBLIC, INTERNAL, CONFIDENTIAL, SECRET)
classified_by: string (Principal)
classified_at: timestamptz
policy_revision: int
```

### egress_policy table

```
id: UUID
source_classification: enum(PUBLIC, INTERNAL, CONFIDENTIAL, SECRET)
destination_class: enum(local_only, approved_private_service, approved_cloud_model, public_internet)
permitted: bool
constraints: jsonb | null
policy_revision: int
effective_at: timestamptz
```

### credential_bindings table

```
id: UUID
credential_ref: string (reference to secure store)
adapter_id: string
audience: string (intended service/resource)
scope_restriction: string | null
principal_id: UUID
created_at: timestamptz
expires_at: timestamptz | null
```

## Authority implications

- Resource classification is part of the authorization context for Grants (SPEC-0003).
- Egress authorization is a separate check from Capability authorization.
- A Grant for `filesystem.read` on a CONFIDENTIAL resource does not authorize sending that data to a public model.

## Failure semantics

- Classification lookup failure → treat as SECRET (fail closed).
- Egress policy evaluation failure → deny egress.
- Missing credential → Operation fails with `credential_unavailable`.

## Concurrency semantics

- Classification changes MUST be serialized per Resource.
- Egress policy evaluation is read-only and needs no locking.

## Security/privacy

- Classification and egress decisions MUST be audited.
- Credential references MUST NOT contain the actual credential value.
- Sentinel-secret tests MUST be part of CI and release gates.

## Compatibility/versioning

- Initial implementation MAY default unclassified Resources to INTERNAL.
- Classification taxonomy MAY be extended in a backward-compatible way.

## Observability/evidence

- Every egress authorization decision MUST produce an audit record.
- Classification assignments and changes MUST be logged.
- Sentinel-secret test results MUST be recorded as evidence artifacts.

## Conformance requirements

- C1: Classification levels and destination classes are enforced.
- C5: Egress authorization order is correct (classification → destination → grant → construct).
- C5: External Resource contents cannot mint authority.
- C6: Sentinel-secret tests pass for all specified locations.
- C6: Credential brokering does not expose secrets to model processes.

## Non-goals

- Automatic classification inference from content.
- Integration with external classification systems.
- Full data loss prevention (DLP) system.
- Encryption at rest/transit (separate infrastructure concern).

### R10: Authentication protection

Authentication decisions (identity verification of Principals, event sources, and adapters) MUST be immune to untrusted data influence.

External Resource contents, model output, package content, and adapter responses MUST NOT alter authentication outcomes.
